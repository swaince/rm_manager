# rm-manager 功能清单与需求描述

**定位**：给自己用的小型需求管理台，覆盖「捕获（头脑风暴/收纳）→ 预研 → 细化 → 排期 → 执行 → 复盘」全漏斗。本地优先、Git 同步、无账号、无服务端、不做协作。空间字段同时承载工作与个人两条线。

**前置决策**：

- 产品形态：桌面应用（Tauri）
- AI 参与度：轻度可选（默认关闭，关键动作处提供可选的 AI 按钮）
- 使用场景：工作 + 个人兼顾（空间字段区分）
- 远程同步：私有 Git 仓库（方案见 `docs/sync-architecture.md`）

## M0 核心模型

- **FR-0.1 统一条目模型**：所有内容（想法/需求/Bug/预研/杂务/头脑风暴会话）是同一种「条目」，用 `type` 区分；每条目一个文件，属性在 frontmatter，正文为 Markdown。
- **FR-0.2 状态机（按类型）**：需求 `inbox → clarifying → refining → ready → scheduled → doing → review → done`；Bug `inbox → ready → scheduled → doing → review → done`；杂务 `inbox → ready → scheduled → doing → done`；想法 `inbox → kept（保留）→（转正离场）/ dropped`；预研 `inbox → doing（时间盒）→ done（结论必填）/ dropped`；会话 `active（进行中）→ concluded（已收敛）/ dropped`。`blocked`、`dropped` 旁路对全部类型可用；状态可自由跳转（不做强制流转），唯一硬门槛是需求进 `ready` 前的就绪检查。
- **FR-0.3 空间与项目**：空间（工作/个人）→ 项目 → 条目三级；顶栏切换空间；搜索、看板、周报均按空间过滤；空间可各配同步远端（见 FR-9.3）。
- **FR-0.4 条目编辑**：属性面板 + Markdown 编辑器（分栏实时预览）；保存即 commit；支持从模板插入正文段落。
- **FR-0.5 双向链接与关系**：正文中 `[[ID]]` 即链接，条目页显示反链；显式关系支持父/子（拆解）、关联、阻塞（被谁阻塞/阻塞谁）。
- **FR-0.6 搜索与筛选**：全文检索（FTS5）+ 结构化筛选（类型/状态/标签/项目/空间/日期/优先级），任何筛选组合可「保存为视图」。
- **FR-0.7 命令面板与键盘流**：Ctrl+K 全局命令面板（新建/跳转/改状态/同步等）；「捕获→整理→改状态→排期」全链路可无鼠标完成。
- **FR-0.8 条目历史与 diff**（P1）：每个条目一条 git 时间线，任意两版 diff 对比，可「恢复到此版本」。

## M1 捕获与收集

- **FR-1.1 全局快捷键速记**：任意应用内按下快捷键 → 迷你输入窗（标题可空，正文即存）→ 落为 inbox 条目，所有字段可空；支持极简符号解析（`#项目`、`@标签`、`明天/周五`），识别不了的原样保留（P1）。
- **FR-1.2 剪贴板收割**：一键把剪贴板内容整段存为条目（从聊天记录/邮件里扒需求），自动附时间戳作为来源信息。
- **FR-1.3 收件箱整理台**：集中处理 inbox——转类型、设空间/项目、加标签、定优先级、必要时直接拆解；支持多选批量；显示「最早一条已堆 N 天」的清理提醒。
- **FR-1.4 快速新建入口**：托盘菜单与主窗口常驻按钮，覆盖无快捷键场景。
- **FR-1.5 首次启动引导**：三步引导（认识空间 → 试记第一条 → 可选连接远端仓库）；预置默认视图（收件箱 / 今日 / 看板）与示例条目，让新手开箱即有样板可循。

## M2 头脑风暴

- **FR-2.1 头脑风暴会话**：新建一个 `type=session` 的「会话」条目，其子条目即想法。发散期不设必填字段，不受就绪检查与排期约束——**不污染需求池**。
- **FR-2.2 发散辅助 [AI 可选]**：给定主题，AI 生成 N 条候选想法进入列表，人工挑选保留；AI 只出草稿，绝不自动落库。
- **FR-2.3 收敛工具**：想法合并/去重/分组；快速打分或排序投票；标记「入选/保留/放弃」。
- **FR-2.4 转正与血缘追溯**：入选的想法一键转正（单条记录改为需求或预研），来源会话的血缘自动保留；放弃的想法留档不删除——半年后翻旧账是常态。

## M3 预研（Spike）

- **FR-3.1 预研条目**：必填「要回答的问题」、时间盒（天）与截止日；细化时勾选「不确定，需预研」可自动创建 spike 并挂上关联。
- **FR-3.2 执行记录**：过程笔记、资料/代码链接、尝试与结果流水账；到期触发提醒（见 M8）。
- **FR-3.3 结论**：出结论才算完成，且「维持现状 / 不做」是合法结论——**预研的产出是知识，不是功能**。
- **FR-3.4 决策记录**：结论可沉淀为 `decisions/` 下的决策记录（背景/候选选项/结论/影响），与相关需求双链；原需求依结论更新描述与估算。
- **FR-3.5 预研视图**：进行中 / 已结论 / 超时未结论三态看板，超时的置顶标红。

## M4 需求细化

- **FR-4.1 细化模板**：背景 / 目标 / 范围（做什么 + **明确不做什么**）/ 验收标准 / 边界与异常；验收标准为 checklist，支持 Given-When-Then 提示；段落模板可自定义。
- **FR-4.2 拆解**：拆解为子条目（建议 ≤2 层，防无限嵌套），子项独立状态/估算/排期，父项进度为子项聚合；拆解建议 [AI 可选]。
- **FR-4.3 就绪检查（DoR）**：自定义 checklist（默认：验收标准已写 / 已估算 / 依赖已明确 / 澄清问题清零），全部满足才能进 `ready`；可豁免但须记录理由。
- **FR-4.4 澄清记录**：问题列表（待答复/已答复），每条含问题、答复、来源人；面向工作场景的对齐留痕，未清零则 DoR 不通过。
- **FR-4.5 估算**：默认三档预算（小 ＜1 天 / 中 1–3 天 / 大 ＞3 天），可在设置切换为理想人日或点数；预研等不确定条目免估算；保留改估记录与一句话理由；未估算条目禁止排期。
- **FR-4.6 验收标准生成/歧义检查 [AI 可选]**：依据背景与目标生成候选验收标准、指出含糊表述，人工确认后写入。

## M5 优先级与规划

- **FR-5.1 优先级**：P0–P3 直接标注；可选打分（只用影响/成本两维 + 一条置信度自问，不引入公式、不显示小数分）仅作参考——**最终优先级永远是人工字段**。
- **FR-5.2 需求池视图**：未排期条目按优先级/分数/日期排序；价值-成本 2x2 矩阵拖拽定位（P2）。
- **FR-5.3 排期**：条目设目标日期或排入某一周（默认本周）；规划面板从需求池拖入，实时显示承诺量 vs 参考容量（近几周平均吞吐，不做精确建模）。
- **FR-5.4 里程碑/版本**：里程碑关联条目集合，自动汇总进度（x/y）与风险（含 blocked 或未估条目即警告）；个人场景可直接当「版本」用。
- **FR-5.5 今日焦点**：每天从 ready/scheduled 挑 1–3 条进「今日」；doing 数超限（WIP 默认 3）只做**软提醒**，不阻止开新。

## M6 跟踪与执行

- **FR-6.1 视图矩阵**：看板（按状态列，拖拽即改状态）、列表（可变列/排序/筛选；**列表内直接改状态与优先级，无需进详情**）、收件箱；日历（按目标日期，P2）、轻量时间线（P2）。
- **FR-6.2 状态流转记录**：每次流转记录时间与停留时长；`doing` 停滞（默认 3 天无更新）自动标黄。
- **FR-6.3 阻塞与等待**：blocked 必填原因 + 等待对象；「等待中」清单按等待对象分组（工作场景的催办视角）；长期阻塞自动进周报风险区。
- **FR-6.4 周回顾与周报**：一键生成上周草稿（完成/进行中/阻塞/新增/放弃/下周计划），内容全部来自真实数据，可复制为 Markdown 直接发人；润色 [AI 可选]。
- **FR-6.5 轻量指标**：每周完成吞吐、平均周期时间（created→done）、需求池净增减；只看趋势，不做燃尽图全家桶。
- **FR-6.6 恢复与撤销**：误删/误改由 git 历史兜底，提供「恢复到此版本」。

## M7 复盘与归档

- **FR-7.1 完成注记**：done 时可选写「实际 vs 预估、教训」，30 秒内可跳过。
- **FR-7.2 清理仪式**：done/dropped 默认折叠归档；每月提醒清理僵尸条目——长期卡住的逐个三选一：继续 / 降级回需求池 / 放弃。
- **FR-7.3 放弃原因**：dropped 必填原因，可选链接替代项（谁替代了它）。
- **FR-7.4 年度回看**（P2）：按年聚合完成条目，自动生成时间线回顾。

## M8 提醒与通知

- **FR-8.1 时间类**：目标日期临近/逾期、spike 时间盒到期、里程碑临近。
- **FR-8.2 停滞类**：doing 停滞、inbox 堆积（> N 天未整理）、blocked 过久。
- **FR-8.3 节奏类**：每日晨间（选今日焦点）、周五周回顾、月初清理，三个固定仪式提醒；均可单独关闭，默认开每日+每周。
- **规则**：统一进通知中心，同一事项不反复打扰。提醒是仪式提示，不是闹钟轰炸——通知过载是个人工具被弃用的第一死因。

## M9 数据与同步

- **FR-9.1 Git 同步引擎**：仓库初始化/克隆向导；同步按钮显示状态（已同步 / 拉取了 N 条更新 / 推送了 N 条 / 离线）；启动自动拉，保存自动本地 commit，定时+退出自动推；失败按网络/认证/冲突三类给出可操作提示。
- **FR-9.2 冲突处理**：冲突条目列表 + 三选一解决（保留双方为副本 / 用本地 / 用远端），解决后自动完成 rebase+push；附一句人话解释冲突原因。
- **FR-9.3 空间级远端映射**：每个空间可单独配置远端仓库或「仅本地」；支持一键更换远端地址（Gitee↔GitHub 迁移不重导数据）。
- **FR-9.4 索引重建**：`index.db` 损坏或丢失时自动/手动一键重建，数据零丢失；vault 路径可配置。
- **FR-9.5 导出**：单条目/查询结果导出 Markdown；项目报告导出（P2）。
- **FR-9.6 附件**：P1 附件存 `attachments/`、相对路径引用；P2 再定大文件是否走 git-lfs（默认不同步，加文件时提示）。
- **FR-9.7 备份快照**（P2）：手动导出 vault zip 到任意位置。

## M10 AI 辅助（全部默认关闭）

- **FR-10.1 模型接入**：OpenAI 兼容接口配置（base_url + api_key + model），兼容国内外常见端点；key 存系统凭据库；提供连通性测试。
- **FR-10.2 动作清单**：各处 [AI 可选] 动作集中管理（拆解建议 / 验收标准 / 头脑风暴发散 / 预研总结 / 周报润色）；每次调用前展示「将要发送的内容」再确认。
- **FR-10.3 约束**：只发送当前展开条目的相关文本，绝不整库外发；输出永远只是草稿，需人工确认才落库；随时可全局关闭。

## 非功能需求

- **NFR-1 单用户单机**：无账号、无自建服务端；数据 = 本地文本文件；同步 = Git 托管。
- **NFR-2 规模**：1 万条目内流畅（搜索 < 200ms）；索引随时可重建。
- **NFR-3 离线**：除同步与 AI 外全部离线可用。
- **NFR-4 键盘优先**：核心链路全部可无鼠标完成。
- **NFR-5 平台**：Windows 优先（两机现状都是 Windows），Tauri 顺带跨平台但不列入 P0 验收。
- **NFR-6 隐私**：明文存本地（换取 git 可 diff/可合并）；敏感内容靠空间级远端隔离处理；凭据入 OS 凭据库。
- **NFR-7 可靠性**：保存即落盘+commit，崩溃最多丢几秒键入；文本真源 + 可重建索引 = 没有「数据库损坏」这个风险面。

## 明确不做（非目标）

- 多人协作、角色权限、评论 @ —— 个人工具，出现第二个用户再说
- 自动排程算法（关键路径、资源平衡）—— 个人量级手工排更快
- 移动端 App / Web 版 —— 需要时用任意 git 客户端读 vault，这是文件格式的免费红利
- 端到端加密 —— 与 git 合并能力天然冲突，用空间隔离代替
- 邮件/IM/日历深度集成、浏览器插件 —— 先用剪贴板收割覆盖
- 插件系统、自定义报表引擎 —— YAGNI

## 分期路线

- **P0（闭环，能日常用起来）**：M0（除 FR-0.8）+ M1 + M4（除 4.6）+ M5（5.1/5.3/5.5）+ M6（6.1 的看板与列表、6.2）+ M9（9.1/9.2/9.4）。头脑风暴与预研在 P0 直接复用「条目 + 父子关系」模型手动跑——一个会话条目挂若干想法子条目，成本近乎为零，专用交互放 P1。
- **P1**：M2 收敛工具、M3 完整（结论/决策记录）、FR-4.3 DoR、M6 其余、M7、M8、M10、FR-0.8、FR-9.6。
- **P2**：时间线/日历视图、打分模型与矩阵、指标面板、附件 LFS、导出与年度回看。
